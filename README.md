# OpsFlow

OpsFlow는 메신저와 문서에 흩어진 운영 요청을 한곳에서 등록하고, 담당자·상태·변경 이력을 연결해 관리하기 위한 프로젝트입니다.

## 문제와 대상 사용자

분산된 운영 요청은 담당자, 현재 상태, 승인 여부와 변경 이력을 한눈에 확인하기 어렵습니다. OpsFlow는 여러 요청을 접수하고 담당자에게 배정하는 소규모 팀을 대상으로 합니다.

- 요청자: 운영 요청을 등록하고 자신의 요청 진행 상태를 확인합니다.
- 담당자: 배정된 요청을 처리하고 검토를 요청합니다.
- 관리자: 담당자를 배정하고 완료를 승인하며 전체 현황을 확인합니다.

## 핵심 흐름

`요청 등록 → 담당자 배정 → 진행 → 검토 → 완료`

현재 프로토타입에서는 요청 목록·상세·등록과 변경 이력 확인 흐름을 제공합니다. 새 요청은 브라우저 `localStorage`에 저장됩니다.

## v1 범위

- 로그인과 사용자 역할
- 운영 요청 등록·조회·수정
- 담당자 배정
- 접수·진행·검토·완료 상태 변경
- 상태·담당자·기간 필터
- 상태별 건수와 처리 현황
- 변경 이력

## 제외 범위

- 실시간 채팅과 외부 서비스 연동
- 복잡한 권한 설정과 모바일 앱
- 통계 대시보드와 고급 디자인
- AI, 결제, Kafka, Kubernetes, 마이크로서비스

## 6주 구현 범위

| 주차 | 목표 | 주요 산출물 |
| --- | --- | --- |
| 1주차 | 화면과 문제 정의 | 요청 목록·상세·등록 화면, 제품 범위 |
| 2주차 | CRUD API | 요청 생성·조회·수정 API |
| 3주차 | Nest.js 전환 | 모듈·서비스·컨트롤러 구조 |
| 4주차 | 데이터베이스와 ORM | 영속 저장, 스키마, 마이그레이션 |
| 5주차 | 인증과 권한 | 역할별 접근과 작업 권한 |
| 6주차 | 통합과 배포 | 전체 흐름 통합, 공개 실행 환경 |

## 설치와 실행

Node.js 22 이상이 필요합니다. 외부 패키지는 사용하지 않습니다.

```bash
git clone https://github.com/mulgko/OpsFlow.git opsflow
cd opsflow
npm install
npm run dev
```

기본 포트가 사용 중이면 다른 포트를 지정할 수 있습니다.

```bash
PORT=3001 npm run dev
```
